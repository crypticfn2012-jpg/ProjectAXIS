Ron Engine Documentation

The engine used by Ron.cool projects. This is where the runtime, systems and project conventions are documented.

Welcome

Ron Engine is a project built for Ron.cool with a simple goal: make it possible to create interactive browser experiences without fighting a huge toolchain. The engine grew from hands-on experimentation with games, first-person systems, 2D experiments, UI, loading screens, asset pipelines and reusable browser code.

Start with the setup guide, then work through the engine systems. Use the reference pages when you need a specific detail.

Ron Engine / History & Backstory

History & Backstory

Where the engine came from and why the current structure exists.

The beginning

The engine started as project code. The same problems kept coming back — loading, input, cameras, HUDs, collision, assets and animation — so the shared parts were pulled out and reused.

As Ron.cool projects got larger, copying the same systems between projects became harder to maintain. That pushed the shared code toward a proper engine structure.

The people

Ron / Ron.cool is the project's creator and driving force. The engine's direction comes from the projects built for Ron.cool and the problems those projects exposed.

Contributor names should only be added here when they have actually contributed to the engine or when Ron.cool has chosen to credit them publicly.

From experiments to systems

Phase What changed
Experiments Small HTML games and interactive pages established the browser-first direction.
Reusable code Input, rendering, HUD and loading patterns started moving into reusable modules.
3D groundwork Three.js-based projects drove camera, player, lighting, asset and animation work.
Engine mindset Shared systems became a deliberate platform instead of one-off code.
Ron.cool ecosystem Apps, games and experiments became the primary testbed for the engine.

Why browser-first?

Ron.cool is a web platform. That changes the engine's priorities: instant loading, simple deployment, URL-addressable projects, familiar web tooling, progressive enhancement, and no mandatory desktop launcher.

Setup & Installation

Download Ron Engine, create a project and get it running in your browser.

1. Download Ron Engine

Download the ProjectAXIS repository and extract it.

↓ Download Ron Engine View source →

2. Find the engine folder

After extracting the repository, open the engine folder. 

ProjectAXIS/
└── engine/
    ├── assets/
    ├── audio/
    ├── core/
    ├── engine/
    ├── graphics/
    ├── input/
    ├── physics/
    ├── ui/
    ├── utils/
    ├── README.md
    └── RonEngine.js

3. Create your project

Make a new folder for your game. Copy the entire engine folder into it. 

my-ron-game/
├── index.html
├── main.js
└── engine/
    ├── assets/
    ├── audio/
    ├── core/
    ├── engine/
    ├── graphics/
    ├── input/
    ├── physics/
    ├── ui/
    ├── utils/
    └── RonEngine.js

4. Create index.html

<!doctype html>
<html lang="en">

<head>

  <meta charset="UTF-8">

  <meta
    name="viewport"
    content="width=device-width, initial-scale=1"
  >

  <title>My Ron Engine Game</title>

</head>

<body>

  <canvas id="game"></canvas>

  <script
    type="module"
    src="./main.js"
  ></script>

</body>

</html>

5. Create main.js

Ron Engine exposes RonEngine and BoxCollider from RonEngine.js. 

import {
  RonEngine,
  BoxCollider
} from "./engine/RonEngine.js";

const canvas = document.querySelector("#game");

const engine = new RonEngine({
  canvas,
  quality: "high"
});

const player = engine.createEntity("Player");

player.addComponent(
  new BoxCollider(player)
);

engine.start();

This is the startup pattern documented by the current Ron Engine source.

6. Use a local web server

Do not open the project by double-clicking index.html.

Ron Engine uses JavaScript modules and browser requests, so the project needs to be served over HTTP.

Python

python -m http.server 8000

Then open: 

http://localhost:8000

VS Code

Alternatively, install the Live Server extension in VS Code, right-click index.html and choose Open with Live Server.

7. Test the engine

Open the browser developer tools with F12 and check the Console.

If the engine loads correctly, you should not have module, asset or JavaScript errors.

If you get a blank screen: check the browser console first. The most common causes are incorrect import paths, missing files or opening the project without a local server.

How the engine starts

index.html
     ↓
main.js
     ↓
RonEngine.js
     ↓
RonEngine
     ├── render loop
     ├── scene
     ├── renderer
     ├── input
     ├── physics
     ├── assets
     ├── UI
     └── lifecycle
     ↓
engine.start()
     ↓
Game running

Common problems

Problem Solution
Module not found Check the import path and make sure the project is being served through HTTP.
Blank page Open DevTools and inspect the Console.
404 error Check the filename, folder name and relative path.
Engine doesn't start Make sure engine.start() is called.
Canvas isn't found Make sure <canvas id="game"> exists before the JavaScript runs.

Ron Engine / Engine Architecture

Engine Architecture

How the runtime is split into systems and how those systems fit together.

High-level architecture

Application
   ↓
Ron Engine Runtime
   ├── Time / Game Loop
   ├── Scene / Entity Model
   ├── Input
   ├── Rendering
   ├── Physics / Collision
   ├── Animation
   ├── Audio
   ├── UI
   └── Asset Loading
          ↓
       Browser APIs
  Canvas · Web Audio · DOM · Fetch · Pointer/Keyboard APIs

Runtime layer

Owns timing, update order, lifecycle and coordination.

Systems layer

Rendering, physics, audio and input provide focused systems.

Game layer

Projects define gameplay rules, content and presentation.

Platform layer

The browser supplies the low-level primitives.

Design principle: systems over monoliths

Ron Engine should prefer small systems with explicit responsibilities. That makes bugs easier to isolate and allows projects to use only the features they need.

Ron Engine / Runtime & Game Loop

Runtime & Game Loop

Understand time, updates, rendering and lifecycle before building complex mechanics.

The main loop

requestAnimationFrame(frame)
        ↓
calculate delta time
        ↓
process input
        ↓
update gameplay
        ↓
update physics
        ↓
update animations
        ↓
render
        ↓
request next frame

Delta time

Use elapsed time rather than assuming a fixed monitor refresh rate. Movement should generally be expressed as velocity × delta time. 

position.x += velocity.x * dt;

Lifecycle

A clean runtime distinguishes initialization, active simulation, pause, resume and shutdown.

Rule of thumb: if a system is changing state every frame, make its update responsibility explicit.

Ron Engine / Rendering

Rendering

The rendering layer, cameras, layers and the boundary between drawing and game logic.

Rendering responsibilities

  • Turn engine state into pixels.
  • Manage cameras and view transforms.
  • Resolve render order and layers.
  • Apply lighting and materials where supported.
  • Keep rendering separate from gameplay rules.

2D

Canvas 2D is a natural foundation for lightweight Ron.cool experiences.

3D

Ron Engine uses Three.js for browser-based 3D work. Three.js is loaded from a CDN rather than requiring a large native toolchain.

Render order

background
→ world
→ transparent effects
→ characters
→ particles
→ UI

Ron Engine / Input

Input

Reading keyboard, mouse, touch and gamepad input.

Input actions

Prefer semantic actions over hard-coding every gameplay system directly to physical keys. 

if (input.pressed("jump")) {
  player.jump();
}

Keyboard and mouse

Browser projects commonly use KeyboardEvent and PointerEvent. First-person games may use Pointer Lock for camera look.

Touch

For mobile, map touch gestures to the same semantic actions.

Ron Engine / Physics & Collision

Physics & Collision

Movement, collision and simple physics concepts for browser games.

Collision comes before polish

Build collision early, then add animation and effects on top.

Simple collision

tryX = position.x + velocity.x * dt;

if (!world.blocked(tryX, position.y)) {
  position.x = tryX;
}

tryY = position.y + velocity.y * dt;

if (!world.blocked(position.x, tryY)) {
  position.y = tryY;
}

Triggers

Separate solid collision from triggers.

Practical rule: solve movement and collision as predictable state transitions before introducing complicated impulses or character controllers.

Animation

Character clips, sprite animation and procedural effects.

Animation types

Type Use
Keyframe / clip Imported character and first-person animations.
Sprite sheet 2D frame-based animation.
Procedural Weapon sway, recoil, camera bob and UI motion.
State-driven Idle → walk → run → jump → fall → land.

Animation state machine

IDLE
 ↓ movement
WALK
 ↓ sprint
RUN
 ↓ jump
AIRBORNE
 ↓ landing
LAND
 ↓ no movement
IDLE

Blend, don't snap

Use interpolation when changing animation weights, camera FOV, weapon sway, UI panels and other visual state.

Ron Engine / Browser Deployment

Browser Deployment

Deploying a project as static files.

Deployment model

Ron Engine is designed for static web deployment. Projects can be hosted on GitHub Pages, Cloudflare Pages and similar services.

Production checklist

  • Use HTTPS.
  • Verify asset paths on the deployed URL.
  • Test hard refreshes.
  • Check console and network errors.
  • Keep user data requests minimal.
  • Use appropriate caching.

Ron.cool integration

Each project should have a stable entry point, clear title, back navigation if needed and mobile behaviour where practical.

Ron Engine / Debugging

Debugging

A simple checklist for tracking down common browser and engine errors.

Debug in layers

  1. Boot: did the module load?
  2. Assets: did files resolve?
  3. Runtime: is the update loop running?
  4. State: are values changing?
  5. Rendering: is the state visible?
  6. Input: are events firing?

Error messages

RON ENGINE: Loading first-person arms
RON ENGINE: Arms model loaded successfully
RON ENGINE: Found animations: 18

Common browser failures

Error Likely cause
Module not found Wrong relative path or file:// usage.
404 asset Incorrect filename, folder or case.
Null DOM element Selector is wrong or script ran too early.
Pointer lock not working Not triggered from a user gesture or focus is elsewhere.

Ron Engine / Performance

Performance

Where frame time usually goes and what to measure.

Measure before optimizing

Use DevTools Performance, FPS counters, render statistics and targeted timers.

Object pooling

Reuse short-lived particles, projectiles and effects.

Spatial partitioning

Limit collision and AI checks to nearby objects.

DOM discipline

Don't update large DOM trees every frame.

Asset budget

Large textures, models and audio can dominate load time.

Frame-time thinking

Ron Engine / Security

Security

Rules for keeping browser projects and connected services safe.

Never put secrets in browser JavaScript. API keys, private tokens and privileged credentials belong on a server.

Ron.cool safety baseline

  • Minimize collection of personal information.
  • Validate user-generated input.
  • Do not trust client-side authorization.
  • Use appropriate database access controls.
  • Provide a security reporting path.

Security.txt

Ron.cool can publish a /.well-known/security.txt file pointing researchers to a security reporting page.

Ron Engine / Contributing

Contributing

A few rules for changes to the engine and documentation.

Start small

Good contributions fix real problems. Documentation fixes, reproducible bug reports, focused utilities and performance measurements are valuable contributions.

Contribution checklist

  1. Describe the problem first.
  2. Keep one change focused.
  3. Don't silently break existing projects.
  4. Include reproduction steps for bugs.
  5. Update documentation when behaviour changes.
  6. Prefer clear names over clever abstractions.

Documentation contributions

When adding a page, answer four questions: what is it, why does it exist, how do I use it, and how do I know it is working?
